# 認証画面（ログイン/サインアップ）実装仕様

## 1. 目的
- ランディングの世界観（暖色系・紙質感・上質な静けさ）と連続する認証体験を提供する
- 迷わずサインインできる導線と、初回ユーザーの安心感を両立する

## 2. 対象範囲
- 画面: `/auth`
- コンポーネント: `src/components/auth/auth-screen.tsx`
- 依存: shadcn/ui（Button, Card, Input, Badge, Separator相当）

## 3. レイアウト仕様
- 2カラム構成
  - 左: 世界観/説明/ミニカード
  - 右: 認証フォーム
- 最大幅: 960px
- 余白: 左右 16px 以上、SPは上下 24px 以上
- SP時: 1カラム（上: 世界観、下: 認証フォーム）

## 4. デザイン指針
- フォント
  - 見出し: Kaisei Decol
  - 本文: Zen Kaku Gothic New
- カラー
  - ベージュ/ブラウン基調 + グリーンアクセント
  - ボタンとアクセントはランディングの主CTAに合わせる
- 背景
  - クリーム色の面にぼかし円/角丸の重なりを軽く配置
- 影・境界
  - 薄いボーダー + 柔らかい影で紙の質感を表現
- ダークモード
  - ランディングの配色を減衰させて反転

## 5. 左カラム（世界観）仕様
- ブランドラベル: 「K E M U R E C O」などの小さなラベル
- メインコピー: ランディングと接続する短文（日本語）
- サブコピー: 記録/ミックス/セッションの価値を2〜3行で補足
- ミニカード: ランディングのカードUIを縮小した要素（例: 今日のフレーバーノート）

## 6. 右カラム（認証フォーム）仕様
- モード切替: サインイン / サインアップ
  - サインアップ時はパスワード方式を必須
- 認証方式
  - Magic Link（メール）
  - パスワード（メール + パスワード）
  - OAuth（Google / X）
- CTA
  - 主CTAはランディングと同系色
  - サブ操作はアウトライン/ゴースト
- 文言
  - すべて日本語に統一（英語混在を避ける）
- 付随リンク
  - 利用規約 / プライバシーポリシーへのリンクをフォーム下部に配置

## 7. 状態・挙動
- 送信中
  - ボタン非活性 + スピナー表示
- 成功/失敗
  - Toastで即時フィードバック
- ログイン後
  - `/` へ遷移
- 認証中の視覚
  - 非活性時は色/影を抑制
- Magic Link送信後
  - 送信先メールを明示し、再送までのカウントダウンを表示
  - 「別のメールで送信」操作を提供

## 8. アクセシビリティ
- すべての入力にLabelを必須
- WCAG AA相当のコントラスト
- キーボード操作でモード切替と送信が可能

## 9. 受け入れ基準
- ランディングと同一トーンの配色/タイポで違和感がない
- SP/PCのレイアウト崩れがない
- すべてのボタン・入力の状態が視覚的に判別できる
- 日本語文言に統一されている

## 10. UX改善（追加採用）
- 入力補助（`inputmode`/`autoCapitalize`/`spellCheck`）でモバイル入力ミスを減らす
- パスワード表示切替のトグルを用意する
- 入力エラーはトーストに加えてインラインで表示する
- 認証方式（Magic Link / パスワード）を次回アクセス時に復元する
- 主要CTAがキーボードで隠れない余白を確保する
