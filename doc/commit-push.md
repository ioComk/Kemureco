# ✅ 実装完了後のコミット・プッシュ運用ルール

実装が完了したと判断した時点で、下記の手順を必ず実施する。

## 1. 事前確認（必須）
- 変更内容が仕様と整合していること
- **LOG.md に実装・意思決定の記録を追記済み**であること
- 仕様変更がある場合は `doc/specification.md` を更新済みであること
- 既存機能に破壊的な影響がないこと（No destructive changes）
- ロジックが **idempotent** であること

## 2. 動作確認（必須）
- `http://localhost:3000` にアクセスし **HTTP 200** を確認
- 追加・変更箇所の主要フローが動作すること
- 可能ならテスト（ユニット/結合）を実行し、失敗がないこと
- `npm run build:cf` が成功すること（Cloudflare デプロイ前提）

## 3. コミット準備
- 不要な差分や一時ファイルが残っていないこと
- フォーマット・Lint の規約に準拠していること
- 追加・変更ファイルの目的が明確であること

## 4. コミット
- コミットメッセージは **Conventional Commits** を使用
- 例: `feat(session): add day detail menu`

## 5. プッシュ
- `feat/*`, `fix/*`, `chore/*` などの短命ブランチからプッシュ
- PR 作成後にレビューを通過して `main` にマージ
- マージ完了後、該当ブランチは削除

---

運用ルールの詳細は `doc/branch.md` を参照する。
